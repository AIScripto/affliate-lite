Decisions needed

Choices that belong to the project owner. The audit does not make them.

DEC-001 · Should publisher postback webhooks be queued asynchronously via Redis/BullMQ or dispatched inline with timeout?

  • Inline dispatch with a strict 3-second timeout and SSRF IP validation (simpler, zero extra infrastructure)
  • Background job queue via Redis/BullMQ (more resilient against publisher endpoint outages, requires Redis instance)

Recommended: Inline dispatch with strict 3-second timeout for current scale; migrate to BullMQ when volume exceeds 10,000 conversions/day.

Sequence is the recommended order to fix things. It follows urgency first, then dependencies (blocked-by), then quick wins, and puts risky changes last. It is a recommendation, not an instruction.
